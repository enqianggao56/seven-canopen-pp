# 八轴定时 PP 修改报告与实机验收

## 行为变化

| 现场现象 | 修改与判据 |
|---|---|
| 编码器波动导致静止轴误报 | 请求位置决定是否需要移动。保持监测另存已触发目标，首次没有已知设定点时使用稳定反馈。轻微位置或速度超差按完整 SYNC 连续计数，恢复即清零。故障、反馈失效、严重偏移及握手异常沿用整组保护。 |
| 起点尚在运动 | 所有在线轴须同时通过速度及连续位置跨度判定。规划、起动、到位、保持分别读取逐轴配置。 |
| 装载后剩余距离改变 | 在装载及触发守卫中，用最新反馈复算编码时间。可恢复变化引起整组重新规划，轴可加入或退出运动组。每次装载和上升沿均来自同一份最新方案。 |
| 邻近编码无法达到 T | 以机械距离、驱动器的轮廓单位及设计上限计算正整数速度和对称加减速度。逐轴反算时间，并在需要时调整公共加速时间。诊断区分连续轮廓不可行、整数轮廓不可行及有界搜索未命中。 |

只有触发前明确拒绝发送的批次可进入重规划。超过重规划次数、重规划失败或发送状态不确定时，控制器锁定后续运动并执行整组失能。首次规划拒绝目标或时间时，操作者可修正目标后重新执行命令。[规划实现](../canopen_pp/trajectory.py) · [反馈与握手实现](../canopen_pp/motion.py)

## 软件验证

本次在仓库虚拟环境运行 `.venv/bin/python -m pytest -q -rs`，430 项通过，2 项实机使能用例在参数测试模式下跳过。这次 pytest 运行未连接实机。后续小位移实测结果见[排除 Node 5 的实机测试记录](pp-hardware-20261124/README.md)。

Node 1–8 的参数化用例使用各轴的 K/C、方向、零点、606Ch 单位和设计限值。测试涵盖单周期波动、连续位置或速度超差、严重偏移、连续静止等待、位置跨度、整组重装、运动轴增减、混合方向、全部保持、逐个节点离线及重试耗尽。测试直接检查批次内各轴的目标、6081h、6083h、6084h 和触发次数。虚拟 CAN 测试另外检查现有 PDO 映射、SYNC 屏障、ACK、故障和部分发送后的失能路径。[逐周期测试](../tests/test_pp_cycles.py) · [虚拟总线握手](../tests/test_pp_motion.py) · [离线节点测试](../tests/test_offline_nodes.py)

| 按实际分辨率构造的输入 | 软件回归判据 |
|---|---|
| Node 1、2 各 110 inc / 5 s，Node 3 为 138 inc / 3 s，Node 4 为 1093 inc / 10 s | 逐个验证原邻域的全部候选超差，新编码合法且反算时间误差 ≤ 0.1 s。 |
| Node 5、6、7 各 76 inc / 3 s | 位移 1.669921875°，6081/6083/6084 为 1/4/4，预计 3.033203125 s。 |
| Node 5、6、7 各从 0° 至 0.1° / 10 s | 目标量化为 5 inc 位移，10 s 超过该位移最慢整数轮廓的时间，拒绝运动。 |
| Node 8 从 0 至 14 mm | T = 2 s 时采用三角轮廓，编码为 4200/4200/4200，预计 2 s。T = 1 s 时连续轮廓不可行，理论最短时间为 2 s。 |

时间断言以最终整数编码独立反算。反馈时序测试使用可控的模拟反馈，虚拟驱动按测试设定时刻回报到位。两者均无法测量真实负载的起动、到位及轴间偏差。[数值回归](../tests/test_trajectory.py)

## 实机验收步骤

1. **记录试验条件。** 保存当前机械标定、目标 JSON、SYNC 周期、各阶段窗口、编码与实测时间容差，以及项目要求的实际同步精度。确认垂直轴已有防坠支撑、抱闸及外部急停可用。记录 CAN 适配器和测量时钟，在主站以 `candump -L can0 > pp-timed-acceptance.log` 开始抓包。
2. **核对坐标与拒绝路径。** 先以默认失能模式执行 `init → status → move-test`，按当前实际位置设置附近的绝对目标。核对方向、每计数机械位移及编码限值。验证上表的无解输入时，先确认对应起点，检查本次命令没有运动触发帧。退出失能模式后以 `CANOPEN_PP_MOTION=1 ./run.sh` 启动。
3. **核对全部静止。** 执行 `init → enable`，把在线轴目标设到各自当前稳定位置，执行 `pp-move`。对照抓包确认连续 3 个完整 SYNC 周期收齐全部在线轴两路 TPDO，速度在阈值内、位置跨度在窗内，随后保持 Operation Enabled，无 001Fh。
4. **从单轴到混合运动。** 在现场许可行程和负载条件下轮换 Node 1–8，先测小位移，再验证上表的可行输入。Node 8 的 14 mm / 2 s 达到该轴设计上限，单独确认试验条件。随后组合正向、反向和静止轴，连续提交两组不同目标。对照终端编码核对每次 RPDO1/2/3 装载。确认所有运动轴的 001Fh 生效于同一 SYNC，Kinco ACK 置位后清位，静止轴无上升沿。记录请求位置、保持参考及两者相邻时的实际反馈。
5. **验证重装与保护。** 在可控反馈试验台上逐轴复现轻微起点变化、单周期保持超差和连续超差。核对重规划日志与抓包，重装期间无上升沿，最终只对最新运动组触发一次。连续超差、反馈丢失或触发结果不确定时核对整组锁定及失能回报。部分离线试验在失能后配置试验节点，重新 `init`，核对在线名单及剩余轴的装载和触发。
6. **计算并签收。** 以触发批次 SYNC 的 TX echo 为零点。逐轴记录首次跨起动窗口、首次稳定进入到位窗口的总线时间，检查清位后连续确认周期及适用的目标到位位。计算每轴到位时间减 T 和组内最晚减最早到位时间。用现场同步测量设备核对实际机械起停，注明 SYNC 采样间隔、负载和测量不确定度，将实测值与验收约定逐项比较。结束时执行 `disable → status → exit`，归档终端日志、抓包与机械测量记录。

默认 0.1 s 用于预测轮廓时间，仓库的 2.0 s 用于反馈到位偏差及组内时间差。实机同步精度需由本次标定、负载和采样条件下的测量确认。[配置](../canopen_pp/config.py)
